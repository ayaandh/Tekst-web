CONTRIBUTING

Make Tekst better.

Tekst is built to be simple, readable, and useful. Contributions help improve the language, interpreter, documentation, tooling, and everything around it.

WAYS TO CONTRIBUTE

There is more than one way to help.

You do not need to work on the interpreter itself to contribute. Bug reports, documentation, examples, experiments, and language improvements are all valuable.

01

Report bugs

Found something that does not work correctly? Open an issue with a clear description and a small example that reproduces the problem.

02

Improve the language

Add language features, improve the interpreter, fix parser or runtime problems, or make existing functionality more reliable.

03

Improve the docs

Documentation is part of the language. Fix unclear explanations, add examples, and keep the reference accurate.

04

Build experiments

Create projects, examples, libraries, tools, or experiments that demonstrate what Tekst can do.

CONTRIBUTION GUIDE

From idea to pull request.

01

Fork

Create your own fork of the Tekst repository so you can work on your changes independently.

02

Clone

Clone your fork locally and open the project in your preferred editor.

03

Build

Build the interpreter and make sure your changes compile before submitting them.

04

Submit

Create a focused pull request explaining what you changed and why.

terminal
git clone https://github.com/ayaandh/Tekst.git
cd Tekst

git checkout -b my-change

g++ -std=c++17 -Wall -Wextra -pedantic src/*.cpp  -o executables\Tekst.exe      
g++ -std=c++17 -Wall -Wextra -pedantic tk/*.cpp  -o executables\tk.exe
PROJECT STRUCTURE

Know where everything lives.

The interpreter is split into focused C++ source and header files for lexing, parsing, values, runtime objects, environments, errors, built-ins, file operations, and the REPL.

├── builtins.h
├── class.cpp
├── class.h

├── environment.h
├── errors.cpp
├── errors.h
├── file_io.cpp
├── file_io.h
├── function.cpp
├── function.h

├── interpreter.h
├── lexer.cpp
├── lexer.h
├── main.cpp
├── parser.cpp
├── parser.h

project

├── LICENSE
└── README.md
Keep interpreter components focused. Lexer logic belongs in the lexer, parsing logic belongs in the parser, runtime behavior belongs in the interpreter and runtime objects, and command-line behavior belongs in the CLI and REPL components.
TEKST STYLE

Keep the language consistent.

Tekst uses fn for normal standalone functions. Methods declared inside classes use def. Constructors use def __init__.

normal function
fn greet(name):
    print("Hello " + name)

greet("Tekst")
class methods
class Person:
    def __init__(self, name):
        self.name = name

    def greet(self):
        print("Hello " + self.name)
When adding examples or documentation, use fn for regular functions and def for methods inside classes.
