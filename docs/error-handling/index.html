Error Handling

Programs encounter invalid input and operations that cannot complete. Tekst's try/catch statements let you respond to runtime errors instead of letting an expected failure interrupt the rest of your program.

When to use error handling

Use error handling around operations that can fail for reasons your program can anticipate: converting user input, performing a calculation with user-provided values, or calling code that may report a runtime failure. A handler gives you a place to explain the issue, choose a safe fallback, or let the user try again.

Error handling is for failures that happen while a program is running. It does not make invalid Tekst syntax valid; syntax and compilation problems still need to be fixed before the program can run.

The basic shape

Write try:, indent the operations you want to protect, and follow that block with catch: and an indented handler. Tekst uses indentation to mark both blocks.

basic_try_catch.tk
try:
    result = 10 / 0
    print(result)
catch:
    print("Could not calculate the result")
  1. Execution enters the try block and runs its statements in order.
  2. If they complete, execution skips the handler and continues after the catch block.
  3. If a runtime error occurs in the protected work, control moves to catch and the handler statements run.

Protect the operations that belong together

Put the potentially failing steps in the try block, including the work that uses their results. In this first version, only the division is protected: the input conversion happens before try, so a conversion error would occur before the handler is active.

divide_by_input.tk
number = int(input("Enter a non-zero number: "))

try:
    result = 100 / number
    print("Result: {result}")
catch:
    print("That value could not be used for this calculation")

In this version, input conversion happens before the try block, so conversion errors are not handled here. To handle conversion and calculation failures with the same handler, move the conversion inside it:

validate_input.tk
try:
    number = int(input("Enter a non-zero number: "))
    result = 100 / number
    print("Result: {result}")
catch:
    print("Enter a valid non-zero number")

Write a useful handler

A handler should help the person using your program understand what happened and what they can do next. Prefer a clear message or a safe recovery action over a silent catch that makes the program appear to have succeeded.

report_error.tk
try:
    amount = int(input("How many items? "))
    print("Preparing {amount} items")
catch:
    print("Please enter the number of items as a whole number")

Keep try blocks focused

Protect only the statements that may fail for the reason you intend to handle. A very large try block can make it hard to tell which operation caused a problem, while a focused block makes the recovery behavior easier to understand and maintain.

  • Keep normal program logic outside the try when it does not need protection.
  • Use messages that describe the action the user can take, not just “something went wrong.”
  • Do not silently ignore a failure if continuing could produce misleading results.

Common mistakes

Incorrect indentation

The catch keyword lines up with try. Statements handled by each block are indented beneath their keyword.

block_structure.tk
try:
    risky_value = int(input("Enter a number: "))
catch:
    print("The input was not a usable number")

print("The program continues here")

Expecting catch to fix a compile error

try/catch handles runtime errors. If the compiler reports invalid syntax or another compile-time problem, fix the source and compile again; the program has not started running yet.
